# MARU 모션 리디자인 계획

## 목표와 현재 상태

MARU 홈을 제품과 공간을 탐색하는 몰입형 쇼핑 페이지로 바꾼다. 스크롤, 이미지, 타이포그래피가 함께 움직이며 기술적인 완성도가 느껴지는 것이 목표다. 이번 요청의 대상은 `/` 홈이라고 가정하며, 사용자의 디자인 방향 답변을 기다리고 있다.

- `git pull --ff-only`: `Already up to date.`
- 기준 커밋: `0f02264`, `Modernize MARU storefront and harden order flows (#3)`.
- 로컬 `main`과 `origin/main`의 앞섬과 뒤처짐: 각각 0.
- 기존 미추적 파일은 보존했다.
- 현재 구현: Next.js 16.2.10, React 19.2.3, Tailwind 4. 전용 애니메이션 패키지는 없다.
- 홈은 서버에서 API 데이터를 병렬 조회하며, 관리자 전시 설정과 상품 정보를 사용한다.
- 제품 이미지 300개가 있다. `public` 안에서 glb, gltf, mp4, webm 파일은 발견하지 못했다.
- 현재 시각 기준은 `.impeccable.md`와 `docs/design-system.md`에 있다. 따뜻한 아이보리, 한국어 명조 제목, 제품 사진, 정적인 편집 구성이 중심이다.
- 현재 모션은 진입 효과와 약한 이미지 확대 수준이다. 이번 요청은 이 기준보다 큰 움직임을 요구한다.
- 로컬 Docker와 개발 서버를 실행했다. 프런트엔드 환경 파일의 API 포트는 8180이고 기본 개발 API는 8081이므로, 이번 실행에만 환경변수로 8081을 지정했다. 환경 파일은 수정하지 않았다.
- 현재 화면은 로컬 브라우저에서 확인했다. 390px에서 문서 가로폭도 390px였다. 제품 흐름 회귀 테스트와 성능 측정은 아직 실행하지 않았다.
- 개발 브라우저에서 Next.js HMR WebSocket 연결 오류를 관찰했다. 새 디자인 검증은 프로덕션 빌드를 기준으로 하여 앱 오류와 개발 연결 오류를 구분한다.

## 비교할 세 방향

| 방향 | 첫인상과 대표 장면 | 기술과 비용 | 판단 |
| --- | --- | --- | --- |
| A. 시네마틱 쇼핑 | 큰 공간 사진이 스크롤에 따라 확장되고, 제품과 소재를 차례로 가까이 보여주는 화면 | Motion, CSS 원근감, 이미지 마스크. 기존 사진 사용 가능. 이미지 품질과 모바일 구도 검증 필요 | 추천. 현재 리빙 상품과 역동적인 연출을 함께 살릴 수 있음 |
| B. 실험적인 테크 | 포인터에 반응하는 입체 오브제와 셰이더 전환을 전면에 배치 | WebGL과 전용 에셋 제작 필요. GPU, 로딩, 터치 대체 경험 검증 비용이 가장 큼 | 기술 쇼케이스의 인상을 가장 강하게 원할 때 선택 |
| C. 에디토리얼 모션 | 대형 한국어 제목, 비대칭 이미지, 빠르고 정교한 텍스트와 화면 전환 | Motion과 CSS 위주. 세 방향 중 렌더링 부하가 낮을 것으로 예상 | 브랜드 인상과 가독성을 중심에 둘 때 선택 |

추천은 A를 기본으로 C의 타이포그래피를 결합하는 것이다. B의 셰이더는 비교 시안에서 효과가 분명할 때 대표 장면 하나에 한정해 검토한다. 세 방향의 모든 효과를 동시에 넣는 것은 추천하지 않는다.

## 추천안의 장면 구성

### 1. 첫 화면: 공간 안으로 들어가기

- 여백을 포함해 화면에 크게 걸리는 MARU 워드마크와 실제 히어로 카피.
- 공간 사진은 첫 렌더부터 보이고, 600~900ms 안에 제목과 CTA의 진입 연출이 끝난다.
- 첫 스크롤 구간에서 사진 프레임이 넓어지고 이미지와 제목이 서로 다른 속도로 이동한다.
- 포인터가 있는 기기에서는 이미지에 작은 원근 변화가 생기고, 포인터가 벗어나면 스프링으로 원위치에 돌아온다.
- CTA는 애니메이션이 끝나기 전에도 클릭할 수 있다. 가격, 검색, 장바구니 진입을 가리지 않는다.
- 좁거나 높이가 낮은 화면에서는 큰 이동을 없애고 정적인 히어로와 짧은 진입만 제공한다.

### 2. 공간 컬렉션: 세 장면을 넘겨보기

- 리빙, 키친, 웰니스의 실제 카테고리 데이터로 구성한다.
- 데스크톱에서는 한쪽의 제목이 잠시 머무는 동안 반대쪽 이미지가 겹쳐 전환된다.
- 장면이 바뀌면 번호, 이미지, 설명이 같은 리듬으로 움직인다.
- 각 장면의 링크는 기존 `/category/[slug]`로 연결한다.
- 모바일에서는 세로 순서와 터치 탐색을 유지한다. 가로 스크롤 강제 변환은 사용하지 않는다.
- 키보드 초점이 보이지 않는 패널에 들어가지 않도록 DOM 순서와 노출 상태를 설계한다.

### 3. 제품: 가까이 살펴보기

- 기존 큐레이션 데이터를 사용한다. 이미지 크기와 여백의 차이로 대표 제품을 강조한다.
- 제품이 화면에 들어올 때 짧은 순차 진입을 적용한다.
- 사진의 원근 변화는 이미지 영역에만 적용하고 상품명, 가격, 찜, 장바구니 조작은 고정한다.
- 판매 정보와 구매 동작은 마우스 오버 여부와 관계없이 접근할 수 있어야 한다.

### 4. 소재 이야기: 확대되는 한 장면

- 관리자에서 활성화한 프로모션의 사진, 제목, 설명, 링크를 사용한다.
- 스크롤에 맞춰 사진이 가까워지고 설명이 차례로 나타나도록 구성한다.
- 전체 화면 전환은 이 장면에서 한 번 사용해 앞선 제품 영역과 리듬을 구분한다.
- 이미지 해상도가 확대에 부족하면 확대 폭을 줄인다. 검증되지 않은 제품 디테일을 생성해 실제 사진처럼 사용하지 않는다.

### 5. 신상품과 서비스: 쇼핑으로 이어가기

- 신상품 탐색과 기존 서비스 정보를 읽기 쉬운 구성으로 마무리한다.
- 하단까지 반복되는 장식 애니메이션은 추가하지 않는다.
- CTA의 눌림, 포커스, 상태 변경 반응을 통일한다.

## 기술 설계

- 기본 후보는 `motion` 하나다. Next.js와 React 구조에서 스크롤, 스프링, 등장 연출을 같은 체계로 관리한다.
- Anime.js는 참고한 연출 원리를 재현하는 데 필요하지 않으면 설치하지 않는다. SVG 경로 연출이 확정되고 이점이 있을 때만 재검토한다.
- [Motion 스크롤 공식 문서](https://motion.dev/docs/react-scroll-animations)의 `useScroll`, `useTransform`과 [React 애니메이션 문서](https://motion.dev/docs/react-animation)의 제스처를 우선 검토한다.
- `HomePage`는 서버 컴포넌트로 유지하고, 모션이 필요한 영역만 작은 클라이언트 컴포넌트로 분리한다.
- 클라이언트 모션 영역은 서버가 전달한 데이터만 사용한다. API 호출 경로나 공통 계약을 복제하지 않는다.
- 스크롤마다 React 상태를 갱신하지 않고 motion value로 처리한다. 이미지 이동은 가능한 transform과 opacity 중심으로 구성한다.
- 마스크 효과는 성능을 측정해 채택한다. 부하가 크면 transform 방식으로 바꾼다.
- [useReducedMotion](https://motion.dev/docs/react-use-reduced-motion)을 사용해 큰 이동, 원근 변화, 고정 스크롤 구간을 정적인 레이아웃으로 전환한다.
- 탭이 비활성 상태이거나 장면이 화면 밖으로 나가면 지속적인 렌더링을 정지한다.
- 브라우저의 자연스러운 스크롤, 뒤로 가기, 링크와 키보드 동작을 보존한다.
- 큰 이미지와 CTA는 JavaScript 실행에 의존하지 않는다. 무거운 효과는 기본 콘텐츠 이후에 초기화한다.

## 변경 범위와 파일

| 위치 | 역할 |
| --- | --- |
| `apps/storefront/src/app/(store)/page.tsx` | 기존 API 조회와 전시 데이터 유지, 새 홈 장면 연결 |
| `apps/storefront/src/components/home/` | 확정된 장면의 모션 컴포넌트. 필요한 것만 생성 |

| `tests/e2e/` | 홈 탐색, 모션 감소, 모바일, 키보드 회귀 시나리오 |
| `.impeccable.md`, `docs/design-system.md` | 실제 적용 후 홈의 모션 규칙과 시각 기준 갱신 |

공통 헤더와 푸터 변경은 홈 연출에 필요한 범위가 확인될 때 결정한다. 상품 상세, 결제, 주문, 관리자 화면의 재설계와 API 또는 DB 변경은 이번 홈 디자인 범위에 포함하지 않는다.

## 실행 순서와 통과 기준

1. 방향 확정과 시안: 현재 데이터로 첫 화면과 컬렉션 장면의 구도를 구체화한다. 첫 화면에서 브랜드, 상품 이미지, 실제 카피, CTA가 함께 식별되어야 한다.
2. 히어로 구현: 데스크톱과 모바일, 모션 감소 설정에서 각각 렌더링한다. 레이아웃 이동과 텍스트 겹침이 없어야 하며 CTA가 즉시 동작해야 한다.
3. 컬렉션과 소재 장면 구현: 전시 데이터와 카테고리 링크를 연결한다. 위아래 스크롤, 창 크기 변경, 키보드 이동에서 장면이 정상적으로 복원되어야 한다.
4. 상품 동작 확인: 홈에서 카테고리, 상품 상세, 찜과 장바구니의 기존 흐름을 확인한다. 상태와 가격을 임의로 가정하지 않는다.
5. QA: 실제 브라우저와 프로덕션 빌드로 아래 검증을 수행하고 결과를 기록한다.
6. PM 검토: 시각 결과, 기능 회귀, 성능 측정과 잔여 위험을 검토한 뒤 구현 완료와 승인 완료를 구분해 보고한다.

## QA 수용 기준

- 390, 768, 1280, 1440px에서 콘텐츠 잘림과 의도하지 않은 가로 스크롤이 없다.
- Chromium과 모바일 WebKit에서 이미지, 카테고리, 상품 CTA가 동작한다.
- 키보드로 탐색할 수 있고 포커스가 보인다. 클릭 영역은 최소 44px이다.
- 모션 감소 설정과 JavaScript 비활성 상태에서도 핵심 제목, 상품 정보와 링크를 사용할 수 있다.
- 관리자에서 숨긴 카테고리와 프로모션의 표시 규칙을 보존하고 빈 데이터에 대응한다.
- 애니메이션 중에도 상품명과 가격이 읽히며 찜과 장바구니 동작을 방해하지 않는다.
- 프로덕션 빌드 기준으로 새로운 콘솔 오류, 이미지 로딩 실패, hydration 오류가 없다.
- 스크롤 전후 장면과 데스크톱, 모바일 캡처를 저장한다. lazy 이미지의 로딩 완료를 확인한 뒤 판단한다.
- 성능 목표: 테스트 환경에서 60fps 지향. 지속적으로 50fps 아래로 떨어지면 해당 효과를 단순화한다.
- 프로덕션 로컬 측정 목표: LCP 2.5초 이내, CLS 0.1 이하. 기준 화면과 변경 화면을 같은 조건에서 각각 3회 측정하고 중앙값과 조건을 기록한다. 현장 사용자 성능을 검증한 것으로 표현하지 않는다.
- 입력 지연은 DevTools로 확인한다. 실사용 INP는 현장 데이터가 필요한 별도 지표로 남긴다.
- 중급 실물 기기를 사용할 수 없으면 모바일 에뮬레이션과 CPU 제한 결과로 표시하며 실기 검증으로 표현하지 않는다.
- `npm run qa`와 `npm run qa:e2e`가 통과해야 한다. 이번 계획 단계에서는 미실행이다.

## 남은 결정

사용자는 추천 계획을 받은 뒤 "구현해봐"라고 지시했다. A 시네마틱 쇼핑에 C의 큰 타이포그래피를 결합해 구현한다. 새 시안 승인 절차를 추가하지 않고 기존 사진과 실제 코드로 진행한다.

## 확정한 구현 방향

- THESIS: 공간 사진과 한국어 제목의 규모, 스크롤 장면의 전환으로 몰입감을 만든다.
- OWN-WORLD: MARU의 아이보리, 짙은 적갈색, Gowun Batang 제목, Noto Sans KR 본문, 실제 생활 사진을 사용한다.
- STORY: 첫 공간, 브랜드 관점, 세 개의 카테고리, 계절의 선택, 소재 이야기, 신상품, 서비스 순서다.
- FIRST VIEWPORT: 큰 한국어 제목과 즉시 클릭 가능한 CTA, 사진을 가로지르는 MARU 워드마크가 함께 보인다.
- FORM: 사용자가 진행을 지시한 A 추천안. 새로운 무작위 콘셉트 선정이나 이미지 시안 단계는 추가하지 않는다. 원근 변화와 스크롤 확대, 고정 사진의 마스크 전환을 사용하며 모바일과 모션 감소 설정은 자연스러운 세로 레이아웃으로 전환한다.

## 구현과 검증 현황

구현 브랜치: `codex/cinematic-home`.

- Motion 13.2.0을 추가했다.
- 한국어 대형 제목, 즉시 사용할 수 있는 CTA, 사진 위 MARU 워드마크를 구현했다.
- 히어로의 스크롤 확대, 포인터 원근 반응, 워드마크 이동을 연결했다.
- 데스크톱 컬렉션은 사진을 고정하고 스크롤에 따라 이미지 마스크를 전환한다. 제목과 카테고리 링크는 실제 문서 흐름에 남긴다.
- 모바일, 높이가 작은 화면, 모션 감소 설정에서는 이미지와 설명을 순서대로 표시한다.
- 소재 사진 확대와 상품 진입 연출을 추가했다. 홈의 장바구니 버튼은 마우스를 올리기 전에도 표시한다.
- 전시 데이터와 공통 상품 계약을 사용한다. HERO 전시 숨김 상태도 반영한다.
- E2E에 스크롤 후 카테고리와 장바구니 탐색, 4개 화면 너비, 모션 감소 전환, JavaScript 비활성 탐색 테스트를 추가했다. Chromium과 모바일 WebKit에 적용하도록 설정했다.
- `npm run qa`: 통과. 린트, TypeScript, 프로덕션 빌드, API 테스트 41개 통과.
- 디자인 정적 검사: 변경 대상에서 탐지 결과 `[]`.
- 독립 코드 리뷰: JavaScript 비활성 데스크톱에서 일부 카테고리 사진이 숨는 문제, 숨김 컬렉션을 가리키는 탐색 링크 문제를 수정했다. 재검토에서 두 수정의 해결을 확인했다. 수정 후 린트, TypeScript를 포함한 프로덕션 빌드, 테스트 파일 구문 검사도 통과했다.
- 브라우저 검증: 대기. 현재 프로세스의 API 주소가 `http://127.0.0.1:8081/api`여서 기존 API 클라이언트의 `/api/v1` 경로와 중복된다. 이번 실행만 주소를 수정하는 명령이 자동 승인 검토에서 `blocked by policy`로 거절됐다. 사용자에게 실행에 한정한 주소 조정 허용을 요청했다. 저장된 환경 파일은 바꾸지 않았다.
- 브라우저에서 현재 구현을 검증하기 전까지 화면 품질, E2E, 성능 목표와 PM 최종 승인은 미확정이다. 오류 화면에서 수집된 성능 수치는 비교 기준으로 사용하지 않는다.
- 이후 사용자가 최소 두 차례 디자인 평가를 요청했다. 독립 평가 2회와 수정 재확인을 수행했고, 별도의 정적 SSR 프리뷰에서 배치를 확인했다. 최종 잠정 Nielsen 점수는 29/40이며 실제 모션과 거래 통합 검증은 포함하지 않는다. 상세 결과와 미해결 사진 문제는 `docs/landing-design-review-2026-09-06.md`에 기록했다.
